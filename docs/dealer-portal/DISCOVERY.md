| D8 | Credit limit | Odoo 19, verified 2026-11-09 against `account` and `sale`. The company switch is `res.company.account_use_credit_limit`. The effective limit is `res.partner.credit_limit` (company-dependent; the company default applies when the partner has no override). `use_partner_credit_limit` is true only when the partner's limit differs from that default. **Used** on the partner form is `credit` (posted receivable residual) plus `credit_to_invoice` (confirmed sales orders not yet invoiced, company currency, from `sale`). Those fields are restricted to accounting groups, so the portal reads them with sudo on the commercial partner only. A negative `credit` is a credit balance, not negative usage. | Grant, 2026-11-09 |
| D9 | Installed apps | Helpdesk is installed. RVSB teams today: General Inquiries (id 1) and RVSB Returns (id 12). There is no Dealer Support team yet. `helpdesk.team` `name`, `company_id`, and `member_ids` are required. Sign, eLearning, Loyalty, Resellers: open. | agent, 2026-11-08 |
| D10 | Payment providers | Stripe is the card provider. Saved cards are tokens and do not open the card form. Opening My Payments does: Odoo 19's Payment Element is created in setup mode with the contact email in `defaultValues.billingDetails`, and Stripe Link texts that email. There is no separate Link `payment.method`. On staging (2026-11-08) the RVSB Stripe provider is disabled and has no keys. The card form disables Link with `wallets.link = never`. Cards and saved cards stay. | Grant, 2026-11-08 |
| D11 | How Approved Dealer is tracked today | Pricelist on the contact, not a tag. `product.template._int_is_dealer_contact` compares the commercial partner's `property_product_pricelist` (website company) with the public user's pricelist. A pending applicant is a `crm.lead` from `/dealer-application` whose contact is still on the public pricelist, so the button stays visible. | Grant / agent, 2026-11-08 |
| D12 | Help & Feedback teams and customer type | Grant, 2026-11-08: tickets go into the existing teams (D9), not a new Dealer Support team. Keep the four kind tags. Live public teams on `/helpdesk` the same day: General Inquiries and RVSB Returns only. Returns and warranty claims use the team whose name contains "return". Feedback and part requests use the team whose name contains "inquir" or "general". Grant, later the same day: warranty goes to the returns team too. Do not hardcode the ids. The ticket also copies the contact's Tags field, using the same names. There is no separate Customer type field on the contact. Live `res.partner` on 2026-11-08 had no customer-type field and no contact tags yet. | Grant, 2026-11-08 |
| D13 | Who can create a portal user | Free signup is off (`website.auth_signup_uninvited` = On invitation) for RV Solar and Battery and Nomadiq. Password reset stays on. Retail guests still get an account only if they click **Create an account** on the order confirmation page (`rvsb_checkout_account`). On a contact, **Send account setup email** only emails the login. On the opportunity, **Create Dealer Account** asks for a pricelist, sets it, tags the contact **RVSB Dealer**, then sends that same email. If that email already signed in, including after checkout, the same login is kept and they get a sign-in email instead. | Grant, 2026-11-08 |
| D14 | Customer type vs the contact | There is no Customer type field on the contact. The contact field is Tags (`category_id`). Grant, 2026-11-08: the ticket tag shows that field. A contact tagged **RVSB Dealer** gets a helpdesk tag of the same name. A contact with no tags adds none. The pricelist still decides dealer pricing and who sees the Help & Feedback hub. It does not choose the ticket tag. The stored pricelist field in Odoo 19 is `specific_property_product_pricelist` (company-dependent). `property_product_pricelist` is computed from it. | Grant, 2026-11-08 |
| D15 | Credit limit fields in Odoo 19 | `res.partner.credit_limit` is company-dependent. Its fallback is the company default (`account_default_credit_limit`), so reading it with the company gives the effective limit. `use_partner_credit_limit` (Partner Limit) is computed as `credit_limit != company default`, and unticking it writes the default back. `account_use_credit_limit` on `res.company` turns the feature on. Used = `credit` (open receivable) + `credit_to_invoice` (sale adds confirmed, not yet invoiced orders, only when `account_use_credit_limit` is on, for `env.company`). | agent, 2026-11-11 |
